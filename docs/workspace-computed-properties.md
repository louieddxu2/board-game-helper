# 自動屬性的準備與設計方向

目前尚未實作公式或自動屬性。本文件依 2026-10-13 的討論更新設計：以可自由輸入的數學表達式為方向，第一階段支援同列數字計算、多個變數、常數、四則運算及括號。以下是實作前的方案，不是已上線功能。

## 已完成的共用基礎

`cellChanges.ts` 的 `WorkspaceCellChange` 描述一筆原始值的變更：列 ID、欄位 ID、修改前與修改後的值。單格編輯、批次修改、貼上、隱藏欄位保存及操作歷史，都透過 `applyWorkspaceCellChanges` 套用這類變更。

同一次操作只複製實際有變更的列；一般欄位值物件每列最多複製一次，只改物件名稱時保留原值物件。未修改列維持原參照，因此區塊保存能維持局部寫入。現行入口使用列 ID 索引定位變更列；列陣列的淺複製仍是線性記憶體成本。

隱藏欄位保存改為一次提交所有變更，使用既有可保存多欄位差異的 `paste-range` 歷史格式，新增列與欄位皆為空陣列；使用者看到的操作名稱是「編輯隱藏欄位」。因此一次保存也是一次復原，動態列表統計和原始資料隨同一提交更新。沒有增加資料庫遷移或歷史格式版本。

型態轉換仍先檢查全部待轉換值，確認沒有錯誤後才保存。其變更紀錄沿用同一種原始值差異；轉換、格式化和顯示責任沒有混進儲存格套用函式。

## 第一階段：同列的自由數字公式

使用者可輸入 `價格 / 次數`、`(價格 + 運費 - 折扣) / 次數 * 0.8` 或 `-(價格 - 折扣)`。不限兩個來源欄位或一個運算子；第一階段的變數來自同列原始數字欄，常數直接寫在公式內。

第一階段支援有限數字、變數、`+ - * /`、一元正負號及括號，遵守先乘除後加減與括號優先。欄位清單協助插入及綁定變數，使用者也可自行命名別名，例如 `p / n`；中文變數名同樣可用。含空白或運算符號的欄名可先使用別名，避免將欄名中的括號誤認為公式括號。同名欄位必須明確選擇，不能自動猜測。

後續可加入次方、函數、條件運算、固定常數綁定及自動屬性引用自動屬性。跨列加總、排名、累計與跨表查找需另外設計依賴範圍，不能沿用「只更新單一物件」的規則。物件名稱 `WorkspaceRow.name` 暫不作為第一階段的數字來源。

## 公式表示與解析

自動屬性仍是 `inputType: 'number'` 的欄位，另外帶有可選公式設定。下列是擬議的儲存形狀，尚未加入 `WorkspaceColumn`：

```ts
formula: {
  version: 1,
  expression: '(p + shipping - discount) / n * 0.8',
  variables: {
    p: { columnId: 'price-id' },
    shipping: { columnId: 'shipping-id' },
    discount: { columnId: 'discount-id' },
    n: { columnId: 'plays-id' },
  },
}
```

公式文字與變數綁定是持久資料；運算樹、編譯計畫、依賴索引及結果是可重建的執行期資料，不同時保存兩份權威公式。變數別名與欄位名稱分開，實際綁定穩定欄位 ID。重新命名欄位只更新介面中的來源欄名，公式別名與綁定仍有效；變更別名時須同步修改完整變數 token，不以部分字串取代。

`formula.version` 表示語言與運算語意版本，和同一語法下編輯公式所產生的計畫版本分開。遇到未支援的版本應明確拒絕，不能移除公式或把結果當成固定值；後續新增語法時同時處理版本相容。

解析流程是「分詞 → 依運算優先序建立運算樹 → 解析變數綁定 → 驗證來源與型別 → 建立依賴」。擬議節點先涵蓋數字常數、欄位參照、一元運算與二元運算，括號決定樹的結構。後續函數與新運算子可擴充節點或運算規則，不必另建一套簡單公式格式。

同一公式定義只解析、驗證一次；每列使用已編譯計畫，不在 render、排序比較器或每個 getter 中重新解析字串。不使用 `eval` 或 `new Function`，未定義變數及未支援符號須指出位置及原因。

為維持手機可操作，公式長度、節點數與巢狀深度需要明確上限；初步可考慮 4,096 字元、512 節點及 32 層，實作時量測後確認。這些是擬議限制，不是現行程式已保證的效能。

## 同一物件的失效與快取

依賴索引只包含運算樹實際引用的來源欄位。`WorkspaceCellChange` 可讓單格、批次、貼上、型態轉換及復原／重做共用失效資訊。

| 變更 | 計算結果的處理 |
| --- | --- |
| 某物件的價格或次數改變 | 該物件中引用此來源的公式過期，按需要重算 |
| 某物件的備註、名稱等無關欄位改變 | 沿用結果 |
| 其他物件更新 | 沿用這個物件的結果 |
| 拖曳列、拖曳欄或重新命名欄位 | 沿用結果與欄位 ID 綁定 |
| 公式或實際使用的綁定改變 | 該公式的既有結果過期，先重算可見列 |
| 首次使用或快取遺失 | 從記憶體中的原始值建立結果 |

快取須核對列 ID、實際引用的來源值及公式計畫版本；不能因整張表的 `changeRevision` 改變而一律清空，也不能只看 row object 參照。無關欄位編輯會產生新 row object，但公式來源可能完全相同。歷史切換或背景工作還須核對目前資料版本，避免發布舊結果。

只含常數的公式沒有列資料依賴，可共用同一計畫的結果。一般同列公式從已載入的原始值計算，不為重算查 DB；結果不寫回 `row.values`、不另建歷史事件，也不額外更新備份版本。

快取按表格與計算情境隔離。備份使用當張表格的暫存計算情境，上傳完成後隨既有暫存資料釋放參照，不把備份的列或結果加入畫面及保存快取。

後續若允許公式引用公式，須在保存及匯入時檢查循環依賴，按依賴順序計算；上游結果真的改變時才讓同一列的下游結果過期。計算計畫與快取應能沿用，第一階段先拒絕這類引用。

## 可見列、錯誤與共用有效值

顯示、搜尋、篩選、排序、數值顏色、欄寬量測及匯出共用有效值入口。現有 `getWorkspaceCellValue` 繼續只讀原始值；計算器是獨立於 React 的純邏輯，備份也能使用。

首屏只計算當前渲染列所需的結果，包括緩衝列。首屏後可依既有背景補齊流程分批建立其餘快取；不每完成一格就觸發一次 React 更新。搜尋、排序及匯出需要完整範圍時，等待必要結果有效後再發布答案。背景工作須可取消，完成前重新核對公式及來源版本。

結果區分有效數值、來源空白、尚未計算與運算錯誤。零是有效數值；空白來源不自動當成零；除以零、非有限結果及來源型別錯誤須顯示可理解的原因。數字運算與排序保留有效數值，顯示位數另外處理，不透過反覆改寫結果取整。

一萬列與五個公式完整建立時，可能有五萬個結果需要計算及快取；首次畫面不應等待它們。這是結果數量，不是耗時保證。活躍的全表搜尋或排序仍有原本的全表成本，「只重算一列公式」不代表整次操作已是固定成本。

## 儲存、欄位操作與交換格式

公式設定屬於欄位定義，IndexedDB 可沿用 `tables`、`tableHeads` 與原始列區塊，無須為結果新增 store。若只更改公式且列參照不變，現行規劃可更新定義、狀態、歷史及 storage revision，保留 `rowChunks`、順序與 `rowPages` payload。

自動欄須在所有寫入入口禁止手動覆寫，涵蓋單格編輯、批次、貼上與隱藏欄位。刪除或改型態的來源欄若有公式引用，應在提交前提示並阻止失效變更。已有手動值的欄位改成公式，設定視窗會說明儲存後取代手動數字；只有儲存才清除原值，歷史記錄保留復原所需的差異。

編輯公式時可顯示少量物件的預覽及錯誤。屬性設定不提供獨立的取消／儲存按鈕，關閉視窗時驗證並儲存；只有儲存成功才更新欄位定義。瀏覽器返回、切表或較新的儲存要求不發布舊草稿。若提供「轉成固定值」，才明確建立目前結果的原始儲存格變更，並保存可復原的公式設定與值差異。

結構化 XLSX 的設定頁保存公式文字與變數綁定，資料頁輸出當時結果供閱讀。匯入時，公式欄的資料頁結果不當成原始輸入，改由匯入的來源值重新計算。一般無公式資訊的表格則按固定值匯入。Excel 中直接修改來源不會讓這種結果匯出自動更新；輸出 Excel 原生公式屬後續獨立能力。

含公式的表格設定應升為 v2，新讀取器兼讀 v1／v2；無公式檔案可沿用 v1。不能只在 v1 設定末端追加公式，因為舊讀取器會忽略它並把結果當成固定值，造成靜默遺失。單表匯入或工作區合併重建欄位 ID 時，必須用同一份 column map 改寫所有公式變數綁定；保留 ID 的備份還原則維持原綁定。匯出不包含執行期快取。

## 實作順序與驗收

1. 先完成表達式表示、解析與驗證，涵蓋多個變數、常數、優先序、括號、一元負號及錯誤位置。
2. 接上同列計算、依賴索引與有效值入口，驗證未修改來源沿用快取。
3. 接上公式設定、可見列、篩選、排序、背景補齊及所有寫入防護。
4. 完成 XLSX v2、舊檔相容、變數 ID 重映射與公式設定的復原／重做。

以一萬列量測首次畫面、來源單格修改到畫面更新、背景工作的連續占用與快取記憶體；與同資料的無公式版本比較。用計算次數及 DB payload 寫入驗證來源單格修改只重算該列相依結果，不額外保存衍生值。另驗證未綁定變數、除零、括號錯誤、改公式、刪來源、取消、匯入重命名、ID 重映射及跨版本檔案。

## 第一階段已完成（2026-10-13）

數字屬性設定可切換「手動輸入／自動計算」。公式是文字框，下方提供 `+ − × ÷ ( )` 與其他原始數字欄位的按鈕，插入游標位置或取代選取文字；不提供數字鍵盤。可直接輸入常數或已綁定的變數。預覽使用第一個物件，取消不儲存草稿。

顯示、可見內容寬度、搜尋、篩選、排序與彙總共用有效值入口；錯誤顯示原因，排序時放在有效值之後，不納入數字彙總。空來源產生空結果，零保留為零，除零及非有限結果顯示錯誤。停止自動計算或轉換類型時保留當下結果；存在計算錯誤時整個轉換不提交。型態轉換與公式修改皆可復原。

可見列立即求值。背景暖快取只處理已載入記憶體的列，依現有 idle 排程切片，不讀 DB、不更新 React 狀態；一般來源編輯不重啟整表暖快取。每次取值核對實際來源，避免背景結果過期。離開表格、刪列及移除公式時釋放對應快取。匯出建立獨立 reader，逐列釋放結果快取，保留常數公式的共用結果；沒有新增衍生資料 store。

一萬列的計算次數與真實 IndexedDB 測試確認：暖快取後修改一列來源，遍歷全部結果仍只重算一次；新增自動欄及單純改公式寫入 0 個 rowChunks、rowPages、rowOrderPages；單格來源編輯只寫入 1 個 chunk、1 個 page，純計算不讀寫 DB。另涵蓋手機游標插入、重新載入、取消、來源刪除防護、固定值轉換，以及 XLSX ID 重映射及整個 Workspace ZIP 備份還原。

初版仍限同列原始數字欄位；不支援函式、跨列、文字運算或公式引用公式。數字採 JavaScript 有限浮點數。實際低價手機的首次畫面、耗電與滑動效能仍需裝置實測，上述測試不等同低價手機的速度保證。
