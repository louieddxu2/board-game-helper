# 自動屬性的準備與設計方向

目前尚未實作公式或自動屬性。本文件記錄 2026-10-08 已完成的資料更新重構，以及下一階段的建議邊界。

## 已完成的共用基礎

`cellChanges.ts` 的 `WorkspaceCellChange` 描述一筆原始值的變更：列 ID、欄位 ID、修改前與修改後的值。單格編輯、批次修改、貼上、隱藏欄位保存及操作歷史，都透過 `applyWorkspaceCellChanges` 套用這類變更。

同一次操作只複製實際有變更的列；一般欄位值物件每列最多複製一次，只改物件名稱時保留原值物件。未修改列維持原參照，因此區塊保存能維持局部寫入。列陣列仍需一次線性遍歷，本次沒有改成不同的記憶體儲存結構。

隱藏欄位保存改為一次提交所有變更，使用既有可保存多欄位差異的 `paste-range` 歷史格式，新增列與欄位皆為空陣列；使用者看到的操作名稱是「編輯隱藏欄位」。因此一次保存也是一次復原，動態列表統計和原始資料隨同一提交更新。沒有增加資料庫遷移或歷史格式版本。

型態轉換仍先檢查全部待轉換值，確認沒有錯誤後才保存。其變更紀錄沿用同一種原始值差異；轉換、格式化和顯示責任沒有混進儲存格套用函式。

## 下一階段建議先做同一列的欄位計算

例如「單價 × 數量 = 小計」。這個範圍可以讓修改一列只影響該列相依的欄位，不必掃描其他九千多列。跨列加總、排名與條件統計需要不同的失效與增量策略，應另行設計。

公式設定屬於欄位定義；參照使用穩定的欄位 ID，顯示時再對應欄位名稱。重新命名或拖曳欄位不應破壞參照。保存設定時檢查不存在的參照與循環相依，建立相依順序；平常修改只重新計算變更欄位可到達的相依欄位。

`WorkspaceRow.name` 和 `WorkspaceRow.values` 目前是原始資料來源。計算結果應先作為可重建的衍生值或快取，避免將一次輸入擴大成多筆原始資料變更、操作歷史及 IndexedDB 寫入。若提供「轉成固定值」，才明確建立原始儲存格變更。

原始欄位輸入仍可用目前的變更紀錄作為失效資訊。復原／重做、貼上、批次修改及型態轉換，都須經過相同的結果失效流程。相依結構或公式設定變更則另有版本，不能只用列的原始值參照判斷結果是否有效。

顯示、搜尋、排序、欄寬量測和匯出，未來需要共用取得「目前有效值」的入口，避免畫面看到計算結果，搜尋或匯出卻讀到原始空值。原始值讀取函式 `getWorkspaceCellValue` 的責任保持不變；新的有效值入口才合併原始值與計算結果。

首屏先取得可見列需要的結果，完整計算應依操作需要或首屏後的背景工作補齊。搜尋、排序與匯出若需要尚未計算的結果，須等到必要結果完整，再產生答案。不能把尚未計算、公式錯誤或已過期結果當作有效空白。

計算結果若需要持久化，必須記錄公式版本與來源版本，遺失或過期時可重建。它與原始值、動態列表的原始資料統計分開；計算欄位的選項統計需明確定義後再加入。匯出公式、匯出結果，以及匯入後如何還原公式設定，都是實作功能前需要決定的使用者行為。

## 本輪的停止點

共用原始值變更與局部保存已能支援下一階段接入相依計算。此時不增加未使用的公式解析器、計算排程器或衍生結果儲存欄位。先決定第一階段的公式範圍與使用方式，再實作具體計算，能避免為尚未確定的需求建立兩套流程。
