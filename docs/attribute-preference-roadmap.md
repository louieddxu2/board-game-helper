# 待辦：從玩家在意的事情發展桌遊屬性

狀態：待研究與驗證。第一個可試用的方向是讓玩家在屬性表選一款遊戲，再選「我想找哪個地方相似」。

## 核心假設

有些樂趣來自一個人在不同情境都會在意的事情，例如欣賞各部分恰好扣合、讀出別人的意圖、預先替可能出錯的環節留後路。可以先從日常活動辨識這些偏好，再問桌遊多大程度提供這種體驗。《花見小路》的整體感，可以和欣賞一套機械或程式設計時的感受對照。

每個候選屬性先寫兩個可獨立回答的問題。以「風險規劃」為例：

- **人的一側**：「事情還沒明朗時，我喜歡想辦法讓幾種結果都有路可走嗎？」也可追問這件事對本人有多重要。
- **遊戲的一側**：「結果還沒揭曉時，玩家有多大空間用眼前的資源或機會，換取未來的備案？」

「平常會這樣做」「擅長這樣做」「覺得這樣做有趣」是三個可分開觀察的問題。第一次試驗以樂趣與選擇下一款遊戲為主。同一個人可以在不同場合想找不同體驗。既有遊戲屬性分數代表遊戲的程度，玩家偏好則用玩家自己的回答取得。

## 研究依據

- **Holland 的人與環境配對**用同一套概念描述人的興趣與環境提供的活動。這提供了兩側對照的結構。職涯研究檢驗的結果包含表現與持續投入，桌遊的再玩意願需要另外驗證。[RIASEC 手冊](https://www.onetcenter.org/dl_files/IP_Manual.pdf) · [職業興趣與適配的統合分析](https://pubmed.ncbi.nlm.nih.gov/26168474/)
- **Schwartz 的基本價值理論**提供「人在意什麼」的詞彙，例如自主、刺激、安全與成就，也提醒我們觀察人在具體情境怎麼取捨。[基本價值理論](https://scholarworks.gvsu.edu/orpc/vol2/iss1/11/)
- **大五人格、HEXACO 與認知需求量表**可用來檢查候選概念是否太寬。以「喜歡動腦」為例，還可追問他愛推理、排流程，還是分析一套系統。[BFI-2](https://escholarship.org/uc/item/16x6n05t) · [HEXACO 特質定義](https://hexaco.org/scaledescriptions) · [認知需求量表](https://doi.org/10.1037/0022-3514.42.1.116)
- **Kelly 的個人構念與 Little 的個人計畫**提供訪談方法。用比較讓玩家說出自己看重的差異，再從他投入過的日常活動找同一種在意。[Kelly 原著](https://www.routledge.com/The-Psychology-of-Personal-Constructs-Volume-1/Kelly/p/book/9780203405970) · [Little 的個人計畫研究](https://journals.sagepub.com/doi/abs/10.1177/0013916583153002)

## 現有屬性的候選對應

以下是待驗證的假設。先用具體例子檢查每個對應，也留意同一個遊戲特徵是否會吸引不同偏好的玩家。定義見[初始屬性](../migrations/0040_attribute_subjects.sql)、[取勝方式](../migrations/0088_activate_win_method_merge.sql)、[限時反應](../migrations/0113_rename_timed_reaction.sql)和[作者的屬性分類文章](https://vocus.cc/article/6a98286cfd89780001ece79f)。

| 現有屬性 | 在遊戲之外也能辨識的在意 |
| --- | --- |
| 整體感、策略／建立引擎 | 欣賞各部分扣合的設計，或享受親手搭出能持續產生效果的系統。 |
| 數字計算、流程計算、邏輯推理、策略／抽象 | 分別是比較數量、排好步驟、由線索推出答案、抽出問題的結構。 |
| 意向推理、互動計算、機制／工人放置 | 分別是讀出別人的意圖、預想彼此的下一步、在有限機會消失前排好先後。工人放置也可能吸引喜歡排流程的人。 |
| 個人拼圖、公共拼圖、公共環境、合作成分 | 分別是自己把東西排好、接著別人的一步解題、透過共同環境影響彼此、為共同成果互相補位。 |
| 長期規劃、隨機應變、設置變化 | 分別是讓眼前決策服務後續目標、變化發生後重排做法、用熟悉的做法處理不同起點。 |
| 運氣成分、隱藏資訊、先備資訊 | 分別提供途中出現變數、部分人掌握資訊、可利用既有規律的情境。享受驚喜、揭開未知、用規律預測是可另外詢問的偏好。 |
| 機制獨特、融入情境 | 對少見做法的好奇，以及喜歡自己的行動在具體情境中有意義。 |
| 取勝方式 | 喜歡一路看見進度，或專注解開關鍵目標。這只涵蓋既有兩端定義的一部分。 |
| 限時反應、等待他人行動、等待他人思考 | 分別是享受即時反應的節奏、在意能否持續參與、在意能否掌握自己的思考節奏。 |

## 待辦

### 一、確認玩家如何描述在意的事

- [ ] 找幾位口味不同的玩家，先請他們說一件日常活動中享受的事，再說一段玩桌遊時想重來一次的經驗。記下原話、例子和原因。
- [ ] 請玩家從三款熟悉的遊戲裡挑出兩款，說明它們在哪個自己在意的地方相似，以及第三款差在哪裡。先聽他的用詞，再核對是否已有相符屬性。
- [ ] 先試「整體感」「意向推理」「長期規劃」。每項整理一個日常題、一個遊戲比較題，以及至少一組能辨識相近概念的遊戲例子。
- [ ] 把「風險規劃」加入訪談。用《農家樂》先準備食物、《阡陌交通》替未來幾種路形留接法和《欲罷不能》決定何時收手，檢查玩家會不會把提前留後路、臨場應變和眼前搏更大回報視為不同的樂趣。

### 二、在屬性表試做按指定屬性找相似遊戲

- [ ] 沿用[屬性表現有的相似遊戲入口](../src/components/AttributeMatrixTable.tsx)。選定一款遊戲後，讓玩家勾一兩個這次想找的地方。例如選《花火》後，分別用「合作成分」或「意向推理」找下一款。這兩項都有[原始匯入紀錄](../migrations/0040_attribute_subjects.sql#L181)。
- [ ] 沿用[相似度計算中的評分證據與涵蓋程度](../src/lib/attributeSimilarity.ts)，用玩家選定的屬性排序。顯示推薦理由和所選屬性的資料缺口。未評分保留未知，涵蓋程度以這次選的屬性計算。
- [ ] 第一版把選項用於當次搜尋，保留整體相似度作比較基準。既有[屬性投票](../src/pages/useAttributesPage.ts)繼續收集「哪款遊戲更具備這個特徵」的證據。玩家喜歡什麼由搜尋時的選擇取得。

### 三、用結果決定是否擴充屬性或做偏好測驗

- [ ] 同一位玩家用同一款起點遊戲看兩組推薦。交替呈現順序，一組用整體相似度，一組按玩家這次選的理由排序。記錄哪組符合預期、是否出現願意試的新遊戲、理由是否準確，以及資料不足的情況。
- [ ] 用訪談未拿來舉例的遊戲檢查對應能否重現。如果玩家能跨遊戲辨識同一種體驗，而且這個差異會改變他想試的作品，再考慮將它加入正式屬性。對「風險規劃」尤其要先比對既有的長期規劃和隨機應變。
- [ ] 如果玩家多次找遊戲時反覆重視類似的事情，再試做可編輯的偏好摘要或短問卷。保留當次選擇，讓玩家能表達這一場想要不同體驗。

## 待決策

- **過程中的隨機要素**暫作描述局中條件的候選名稱。優先驗證玩家在意的是驚喜、拿到新條件後解題、事前留後路，還是決定何時收手。這會影響它適合當推薦理由、篩選條件或新屬性的參照。
- **風險規劃**與 **Push Your Luck** 各有候選遊戲體驗。前者用備案與保留選擇來試評，後者用是否拿已到手的成果換取更多回報來試評。[BGG 機制定義](https://boardgamegeek.com/boardgamemechanic/2661/push-your-luck)
- 若未來要修正文章中的作者參考分數，先核對遊戲版本、匯入批次、原始列與原值。更正的對象是能確認來源的原始直接評分。
