# D1 讀取預算與快取邊界

本文件描述日常操作的架構上限。Cloudflare 的 `rows_read` 可能把索引巡覽列算入，因此數字不是「回傳 JSON 筆數」，但查詢必須維持在指定索引或固定聚合列，不可退回全表掃描。

| 操作 | 本機優先行為 | 快取失效後的 D1 範圍 |
|---|---|---|
| 首頁 | 先顯示 IndexedDB 舊內容，背景更新 | 固定首頁 ID 聚合與少量被引用實體 |
| 遊戲列表 | 先顯示本機總表；10 分鐘後查版本差額；每週重抓總表 | 差額為版本索引命中的變更列；每週總表為預先聚合分塊，不掃 games/rules |
| 登入者目錄 | 與遊戲列表共用同一份本機總表 | 一般使用者只顯示公開數；editor 顯示預先聚合的總數，不另查 games |
| 公共 Tag | 先顯示本機公共 Tag 目錄；每週同步 | 版本索引命中的 Tag 變更列，不 JOIN alias/rule_tags |
| 屬性總表 | 先顯示 IndexedDB 的完整快照；同步檢查每 10 分鐘執行，快照本身每週更新 | 只讀 `attribute_catalog_snapshot_state` 與目前 generation 的分塊；同步時只讀 `(catalog_version, entry_key)` 索引命中的增量列，每批最多 80 列，不掃描 score states、subjects 或 candidates |
| 單款遊戲 | 一小時內直接使用 IndexedDB；過期內容先顯示再背景更新 | 只查該遊戲及該遊戲規則，不查其他遊戲 |
| 規則重要票 | 公開總票數隨規則列取得；本人投票清單快取 10 分鐘 | 個人狀態只走 `(user_id, game_id)` 索引並讀回自己在該遊戲投過的列；投票寫入後只讀 1 列規則確認總數 |
| 一般帳號頁 | 不讀規則活動 | 只回傳 session 中的使用者；editor/admin 才執行最多各 100 筆活動查詢 |
| 收藏首頁 | 本機畫面優先；私人狀態不共用公共快取 | 受固定 LIMIT 與指定遊戲 ID 限制 |
| GeekGroup 收藏 CSV | 只在 IndexedDB 保存去重後的 BGG ID 索引；CSV 的收藏狀態、遊玩次數、私人評分等欄位不進公共資料庫 | 目前不寫 `games` 或 `game_external_ids`；若未來要跨裝置保存，應另建使用者收藏表，不得把收藏資料混入共用遊戲實體 |
| 管理 Tag | 僅管理員主動開啟 | 可讀 active tags、rule_tags 使用量與 aliases；不屬於公共高頻路徑 |
| 屬性比較題目 | Worker 先在記憶體抽出 1～200 的槽位編號，取得一個低信心度「遊戲＋屬性」項目，再固定屬性隨機抽第二款遊戲 | 候選查詢直接使用 score-state 索引與 BGG 資格條件；名稱讀取已保存欄位，近期活動只讀最新 5 列回答快照，極端範例使用 score-first／random-key 索引，不重新展開 subject views；不掃描 200 列候選池。本機 100 次完整題目請求實測 `rows_read` 為 44～99，未超過 100 列 |
| 屬性比較題目（我的收藏） | 先使用屬性總表的 IndexedDB 快取，在本機以 BGG ID 比對並抽題；不另外下載收藏目錄 | 只有屬性總表快取不存在時才取得版本化快照；不再呼叫未受限的 `vote-subjects` 目錄查詢 |
| 屬性投票送出 | 先以 response_id 去重，再取得涉及之「屬性＋遊戲狀態」短期寫入鎖，最後以單一 D1 batch 原子寫入 | 一次回答只寫 1 筆 durable response（包含兩個分數、比較結果與近期動態）、最多 2 個 state；不再同步寫 3 筆事件、pair_stats 或另一筆 feed。現有局部鎖、score state catalog trigger 與必要索引維護後，本機完整回答實測最高為讀 38、寫 27；必須以 D1 metrics 驗證，不可只看 SQL statement 數量 |
| 屬性總表背景建立 | 初始 migration 建立第一代快照；之後僅由每週排程建立新 generation | 讀取完整屬性來源並寫入新的 snapshot generation；不在公開請求或投票熱路徑執行。建立完成後，投票、候選與遊戲主體變更由觸發器寫入增量目錄 |
| 完整資料匯出 | 無自動呼叫 | 會讀取全部公開資料，所以只允許管理員人工執行，禁止列為公共快取端點 |

守門規則：

- 前端不得出現 `fresh`／`force` 參數；需要最新資料時先標記對應本機快取失效，再走同一個 cache-first 函式。
- 遊戲搜尋、目錄與公共 Tag 不可繞過版本化總表直接查資料表。
- 完整匯出不可加入公開讀取或跨站公共快取清單。
- 每日保留單一排程，同時清理匿名瀏覽去重資料、舊統計與過期 session；每週總表也由同一排程的星期判斷執行。
- 新增高頻讀取端點時，必須補測試說明快取命中、過期備援及 D1 查詢範圍。
- 屬性總表與遊戲列表各自擁有版本游標與 IndexedDB 快取；投票頁的「我的收藏」直接重用屬性總表快取，在本機完成 BGG ID 交集與題目抽選。屬性總表以自己的 snapshot、delta entries 與 `throughVersion` 同步，遊戲列表的變更不需要讓屬性總表重新讀完整資料。
- 舊的 `GET /api/attributes/vote-subjects` 已停用並不再查詢 D1；不能讓舊書籤或舊前端重新觸發未受限的主體目錄掃描。
- 公開遊戲頁禁止 `COUNT` 或 JOIN 投票明細；規則列上的聚合票數由唯一投票列的 INSERT/DELETE trigger 原子維護，且投票不得改動規則內容版本時間。
