# 玩家自選差距大的遊戲時，整張排序能否更快排對？

以整個目錄的先後順序為採用標準。55 款模擬中，整票模型在兩種玩家分歧程度下都更早修正最明顯的顛倒。500 票後，意見接近時兩種模型的整體排序正確率相差不到半個百分點，現行略高。意見分散時整票領先 1.62 個百分點。這是為期 500 票的合成實驗，實際採用仍取決於真實玩家的分歧與選款分布。

完整排序早已保存。現行基準是從原票移除參考遊戲，再用正式的中心向外相鄰比較與 Glicko 更新。以下所有模型都只使用玩家放進比較欄的自選遊戲。涉及參考的實驗會另外提供一筆有明確來源的相對判斷。研究腳本獨立於網站與 Worker。[原票格式與展開順序](../src/shared/attributeRankingBallot.ts) · [現行公式](../worker/data/attributeScoring.ts)

## 55 款遊戲有多少排對

0 至 10 分各有五款。把五款 2 分遊戲的起始值設為 8，把五款 8 分遊戲的起始值設為 2，其餘 45 款從真值出發，初始 RD 都是 1.5。每票從 55 款隨機取六款，只保留真值跨度至少 8 分的組合，用以模擬玩家傾向挑差距大的遊戲。每個情境以 100 組種子各投 500 張票，每組的選款、方向與判斷在兩模型之間完全相同。全部使用訪客權重與自選遊戲。

一共 1,375 對遊戲有明確高低，起初排對 80%。正確率只認真值較高的遊戲在輸出中也嚴格較高。真值相同的遊戲不列入分母。沿用目錄分數的小數兩位精度，若真值不同而輸出同分，算尚未排對。另檢查真值只差一分的 250 對，以及原先完全顛倒的 2 分組對 8 分組共 25 對。整榜全對要求所有 1,375 對都排對。[目錄分數精度](../worker/data/attributeResponseContext.ts)

- **玩家意見接近。** 每款的感受值在真值上下 2 分內變動。100、250、500 票後，現行整榜正確率依序為 84.90%、92.81%、96.82%，整票為 86.49%、93.14%、96.37%。整票讓 25 對明顯顛倒全部修正並守住的中位時間為 173 票，現行約 235 票，兩者都在 100 輪中達成。但到了 500 票，只差一分的遊戲由現行排對 82.99%，整票排對 80.09%。
- **玩家意見分散。** 將波動放寬到上下 5 分。100、250、500 票後，現行整榜正確率依序為 83.38%、88.90%、93.43%，整票為 85.20%、91.78%、95.05%。到 500 票時，只差一分的遊戲由現行排對 75.82%，整票排對 77.34%。整票有 99 輪整榜正確率較高，另一次相同。所有 25 對顛倒全部修正並守住的中位時間，整票為 237 票（100 輪達成），現行為 360 票（92 輪達成）。
- **整榜全對。** 兩個情境、兩種模型在第 500 票都沒有任何一輪將 1,375 對全部排對。修正原先的 25 對大錯之後，仍可能把原本正確的相鄰層級排反或列為同分。第 500 票整票相對現行的平均正確率差，意見接近時為 −0.45 個百分點（跨種子的配對近似 95% 區間 −0.57 至 −0.32），意見分散時為 +1.62 個百分點（+1.50 至 +1.74）。

玩家的感受偏差從各情境範圍內的整數等機率抽取，感受值截在 0 至 10，同分時隨機排先後。「守住」從最後一次修正全部 25 對的那張票起算，要求一路維持到第 500 票且至少持續 50 票，中位數只計達成的輪次。模擬保留既有評分大致正確、少數層級顛倒的起點。其他初始錯序、取樣偏好或可信度分布可能改變結果。重跑指令為 `node --import tsx scripts/research-ranking-order.ts`。[55 款排序實驗](../scripts/research-ranking-order.ts)

### 名次相關與線性迴歸的交叉檢查

對照值是 55 款遊戲的已知模擬真值。每輪投完 500 票後，對同一批遊戲算 Spearman 名次相關（同分取平均名次），再以模型最終分數解釋真值，做含截距的單變量線性迴歸。下列 R² 是在該輪 55 款上擬合的結果。100 輪的數字是逐輪計算後的平均，所有遊戲沿用目錄發布的小數兩位精度。[計算腳本](../scripts/research-ranking-order.ts)

- **先前逐款展示的例子。** 意見接近情境的第一輪，整票排對 1,304 對、排反 33 對、另有 38 對未分高低。現行排對 1,298 對、排反 61 對、16 對未分高低。整票的名次相關為 0.9811，現行為 0.9717。迴歸 R² 分別為 0.9717 與 0.9502。
- **意見接近的 100 輪。** 整票與現行的平均名次相關分別為 0.9851、0.9804，平均 R² 為 0.9760、0.9583。每輪 1,375 對中，整票平均有 23.68 對排反、26.26 對輸出同分，現行有 40.84 對排反、2.93 對同分。整票減少了約 17 對顛倒，卻增加約 23 對平手。要求分出正確高低時，現行因此領先 0.45 個百分點。
- **意見分散的 100 輪。** 整票與現行的平均名次相關為 0.9677、0.9516，平均 R² 為 0.9470、0.9091。整票每輪平均有 65.33 對排反、2.79 對同分，現行為 89.44 對排反、0.93 對同分。整票在這個情境也有較多配對能分出正確高低。

若採用標準是榜單要分出正確高低，就直接計算排對幾對，並分別檢視排反與同分。名次相關補充衡量整份榜單的名次接近程度。R² 衡量線性關係，斜率與截距可以吸收分數尺度的改變。即使把整張榜反過來也可能得到 R² = 1，因此它只能作為輔助。評估真實玩家時，需用未參與計分的獨立排序作對照。

## 先前的 24 款實驗與參數敏感度

每種情境使用 64 個種子，每個種子投 160 張六款排序票。每個模型重放完全相同的票。24 款遊戲的合成真值分布在 0.3–9.7，間距不等，初始 RD 混合 0.65、1.5、2.5，初始平均絕對誤差為 1.27 分。特別把真值 2.3 的遊戲設為 7.5、RD 0.65，把真值 7.7 的遊戲設為 2.5、RD 2.5。這讓模型必須推翻一筆高可信度的錯誤。

大跨度情境每票從六個程度區間各挑一款，平均最高與最低相差 7.95 分。三組大跨度實驗共用選款、角色、題目方向與初始狀態。每位玩家為每款遊戲產生一次帶有雜訊的判斷，再排成一張票。這也保留同票比較之間的相關性。小跨度對照改選連續六款，平均跨度 1.97 分。兩端遊戲的曝光機會因此較少。這些抽樣方式用來測假設，正式站玩家的選款和分歧分布仍待量測。

## 一張票如何改變分數與 RD

整票候選使用 Plackett–Luce 的排序概似。按 `highPole` 換回屬性的標準方向後，第一名與全組比較，第二名與餘下遊戲比較，依序到倒數第二名。每一步用遊戲既有分數預測選擇的機率。演算法用整張排序的一次聯合更新來修正原分數，RD 較小的遊戲通常移動較少。它沒有指定名次對應的分數或固定分差。[Plackett–Luce 模型與自選子集](https://hturner.github.io/PlackettLuce/articles/Overview.html)

實驗以現有 0–10 尺度設定斜率 `β = ln(10)/10`，每款的先驗變異數為 RD²。在票前分數求一次 Newton 更新，利用整張票的曲率矩陣及先驗精度求逆，取對角線作為票後邊際變異數。跨票只攜帶分數與 RD。這是可在線更新的近似，會丟失跨票相關性。合成的訪客、會員、編輯者機率為 60%、30%、10%，沿用 1、1.5、2 的整票權重。此實驗沒有假設編輯者判斷更準。Gumbel 雜訊尺度為 1/β，同變異數常態組的標準差約 5.57，意見較一致組為 1.5。[研究模型](../scripts/ranking-research/models.ts)

為避免票長主導比較，在所有分數相等時，把整張票的概似曲率對角總和校準到 `n−1` 次普通等分二選一的量級。對 n 款，排序概似乘數為 `(n−1) / [2(n−Hₙ)]`，其中 Hₙ 是前 n 個倒數之和。一次乘上角色權重。這只是控制初始資訊量的實驗選擇。同票 100 款到底該帶來多少總更新，仍是產品決策。另測一個固定為一次二選一總量的版本。

| 同分、RD 3 的一張訪客票 | 現行，各款絕對移動總和／平均票後 RD | 整票，隨款數調整 | 整票，固定一次二選一總量 |
| --- | ---: | ---: | ---: |
| 2 款 | 1.75／2.86 | 1.67／2.85 | 1.67／2.85 |
| 6 款 | 2.11／2.77 | 4.75／2.76 | 1.07／2.94 |
| 18 款 | 3.18／2.74 | 13.54／2.74 | 0.90／2.98 |
| 100 款 | 10.48／2.73 | 70.79／2.73 | 0.80／3.00 |

即使平均 RD 類似，100 款票造成的總分數移動仍可相差近七倍。在大跨度 Gumbel 組，固定一次二選一總量使最終誤差成為 0.842，平均 RD 1.165。按款數調整版為 0.670、0.768。將同一批票倒序重跑，固定總量版的差異只有 0.028 分，但 64 個種子都沒有持續達標。只壓低波動也可能讓可信度已經設錯的遊戲很難翻身。

在意見較一致組，現行與整票的「真值落在估分 ±1.96 RD 內」比例分別為 93.9%、70.9%。探索性地把整票斜率加倍，同時調低概似權重以維持等分時的曲率，該組最終誤差降為 0.642、涵蓋率升為 95.2%。但同樣設定在大跨度 Gumbel 組會把誤差從 0.670 提到 0.937。這些涵蓋率是用已知合成真值做的校準檢查。RD 能降到多小，應用保留票與獨立人工評分驗證。

## 參考遊戲可以定位多少

另外建立 12 款真值介於 6.1–9.5 的遊戲，初始分數整體低估約 2.5 分。即使內部先後全對，整組在量尺上的高度仍缺乏依據。實驗每票隨機挑一款自選遊戲，假設玩家有一半機會能明確確認它與 8.5 分參考遊戲的相對位置。沿用該玩家排自選遊戲時的同一次判斷，參考遊戲的感受值另抽一次雜訊。當玩家確認時，從同票總量保留半次二選一的權重給這個單向比較，只更新自選款。未確認時完整沿用自選排序。參考狀態與直接評分次數都有斷言檢查。

160 票後，自選整票的絕對誤差為 **2.549**，加入單向確認後為 **2.465**，錯序率從 **2.89%** 到 **2.68%**。在原本就橫跨大部分量尺的 Gumbel 組，絕對誤差只從 0.670 到 0.668。這支持狹窄遊戲群存在定位價值，也顯示效果有限。高分群加入參考後，估分 ±1.96 RD 仍只涵蓋 2.9% 的真值。固定參考分數、確認率、參考強度都是這次的假設。模型也尚未把參考值本身的不確定性傳給自選遊戲。

**把預填當判斷會使同一份玩家證據得出不同分數。** 負對照讓不認識參考的玩家一律把自選遊戲接在預填項目後面。將相同自選順序與 160 張全未確認的票，分別以高端或低端朝上重放。依題目方向換算後，玩家給的自選先後完全相同。採計預填位置會讓每款最終分數平均差 **1.35**，最大差 **1.91**。只採明確確認時兩次逐款完全相同。自選遊戲可以照常投票，玩家認識範例或願意依顯示數字作定位，應由另外可辨識的操作表達。

**編輯者權限是另一個決策。** 在大跨度組共 10,240 張票的模擬中，5,122 張帶有明確確認。若再限編輯者，剩 473 張。這只量出訊號減少的幅度，角色本身無法證明判斷品質。若採權限方案，需獨立決定採計哪些範例比較、是否更新參考端，以及採投票時或重算時的角色。任一方案都不需把畫面上的分數再寫成直接評分。

## 人工修正後，用哪個歷史狀態重算

以相同 80 張票從原始資料重跑。把一款自選遊戲最早的一筆人工評分從 2 改成 7，重算後該款由 **3.414** 變為 **5.082**。其餘自選遊戲因過去共同出現，最大連帶改變 **0.350** 分。人工評分次數仍為 1。這個案例只改那一筆來源資料，重放既有排序，並驗證同一歷史能產生相同結果。

接著把參考遊戲的人工分數從 9.5 改為 8.5。這裡額外假設所有確認票都有可驗證的顯示分數快照，並測兩種意義。

| 重算規則 | 這款自選遊戲的重算分數 | 規則回答的問題 |
| --- | ---: | --- |
| 固定使用投票時的參考快照 | 5.082 | 玩家當時依畫面上的 9.5 作數值定位。改正參考資料後，仍保留當時的意思。 |
| 使用本次重算走到該票之前的參考分數 | 5.059 | 玩家判斷的是兩款遊戲誰更具備該屬性。更正參考的早期資料後，新的位置會傳給自選遊戲。本例各款最大差 0.050。 |
| 將同一批票當作只有現行 v1 欄位 | 5.007 | 只有自選遊戲的先後能確定。兩次參考人工分數不同，此路徑的逐款結果完全相同。 |

另一個實驗讓其他玩家在稍後對參考遊戲新增一筆直接評分。假設這批票使用相同目錄快照，將這筆評分放在第 40 或 80 張排序票之後，快照規則下自選分數逐款相同。按票前狀態定位的規則下，兩次最終最大差 0.002 分。後續事件應從它在歷史中出現的位置生效。現行完整重算會先彙總直接評分、建立初始狀態，再處理比較。要實作逐票歷史參考值，必須另外定義怎麼從這條歷史取得當時狀態。[直接評分彙總與比較重算](../worker/data/attributeReplayCalculation.ts)

現行 v1 有參考 subject ID 與位置，缺少投票時看到的參考分數，也缺少玩家確認。建議舊票先只重用自選順序。未來若採快照，要記下明確確認的對象、方向、玩家實際看到的數值與可驗證來源，尤其要容納離線使用舊目錄的情況。若採重算時點，應從指定版本的初始人工資料按確定順序重放，避免用今天的最終分數回填早期票。線上票已有伺服器決定的權重，現行完整歷史重算會反映角色變動。選用何時的角色也應寫進新規則版本。[線上計分進度](../worker/workflows/attributeOnlineScoring.ts)

## 計算成本與採用條件

- **現行完整 API 實測。** 本機重新執行 `npm run check:attribute-cost`，13 種情境通過。訪客六款每票平均 119.0 讀／30.3 寫，相同六款十人同時為 56.0／7.8，不同六款十人同時為 88.4／34.8，100 款為 1,697.8／331.1。這是包含額度檢查的 Miniflare D1 fixture，併發結果受合批時機影響。[成本測試範圍](attribute-request-cost.md)
- **候選模型的 CPU。** 本機 Node 24，七組暖機後計時取中位數，每張六款票的現行／整票純計分約 0.001／0.005 ms，100 款約 0.019／2.19 ms。研究版用密集矩陣，時間為 O(n³)、暫存空間 O(n²)。線上與分段重算都要評估長票及同批多張長票的 Worker CPU。
- **儲存與 D1 的估計。** 自選整票可用同一張原票、同一批自選遊戲的分數與 RD 在 Worker 記憶體計算，只落盤變動的自選狀態。單向參考若走重算時點，要再取得被確認的參考狀態。可信快照則增加票據位元組與驗證成本。兩者在此設計都不需寫回參考狀態。候選模型尚未接上完整 HTTP／D1 路徑，實際讀寫列數、快取差額和 CPU 必須在同一 fixture A/B 後才能聲稱成本相當。
- **維持既有收票保證。** 若進入實作，保留先保存原票、依 responseId 去重、伺服器租約合批、游標與計分同交易、既有每日維護補算。整票更新要同時接入增量、完整及分段重算，指定模型版本、活動及比較次數的意義，並驗證舊 metadata 無法覆蓋新分數。沿用現行排程，手機完成上傳即可離開。[收票與故障補算](attribute-vote-ingestion.md)

最有辨識力的下一次比較，是把實際已保存的自選排序依時間切成訓練與保留票，只用較早資料估初始分數、分歧尺度及票權重，測能否預測較晚玩家的排序。依投票前可得的分數跨度、RD、票長分組，另用獨立校對的人工分數驗證 0–10 定位及 RD 涵蓋率，並重做人工修訂回放。舊票足以檢驗自選整票。要驗證單向參考的真實效益，還需要能辨識玩家確認的資料。

## 重現

在專案根目錄執行 `node --import tsx scripts/research-ranking-model.ts`。輸出每個種子群組的樣本特徵、各時點錯序與誤差、RD 涵蓋率、反向重放、人工修正與每票成本。分數與種子結果可重現，CPU 計時隨機器負載變動。斷言另檢查兩款解析解、角色權重、雙極題方向、未選遊戲、未確認參考、直接評分次數及參考狀態。[實驗入口](../scripts/research-ranking-model.ts) · [抽樣與量測](../scripts/ranking-research/simulation.ts)
