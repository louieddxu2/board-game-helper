# 取勝方式合併：啟用設計與驗收

狀態：設計，尚未執行 migration 或啟用。依據 2026-09-08 預覽（公開目錄版本 8109）與目前程式碼。

## 保持不變

- 固定 0＝得分取勝、10＝條件取勝。投票題可反向，儲存與瀏覽固定方向。
- 初始值使用已同意的平均公式；五款校正只套用在合併初始值，不修改舊投票。快餐兩筆來源不校正。
- 兩個舊屬性、原文、投票及直接評分歷史保留。合併來源的票數分開保存，不加總成合併屬性的投票數。
- 正式部署、遠端 migration 與 push 不在本次工作範圍。

## 已確認的相容性問題

1. `worker/data/attributeScoring.ts` 的 `applyDirectRating` 在 evidenceCount＝0 時把分數直接改成首次輸入值。若只寫入平均初始值而保持零票，首次投票會完全抹去初始值。
2. `worker/data/attributes.ts` 的 `initializeAttributeMergeRebuild` 會清空全部狀態，從 5 分重建。沒有獨立初始值來源時，遊戲合併或背景重建會遺失換算結果。
3. `responseContextAndStates` 目前要求屬性 is_active＝1。直接停用兩個舊屬性會令仍在離線佇列的合法舊題失敗。
4. 目前範例抽取與相近遊戲依 evidenceCount 判定有無資料。若新屬性沒有任何新票，換算初始值會被當成未知；填一張假票雖能繞過判斷，但不符合不增加投票的要求。

## 下一階段分批實作

### A. 獨立初始值與來源

- 新增獨立的合併批次與每款初始值紀錄，保存來源兩個 attribute ID、subject ID、完整來源狀態、版本、時間、公式版本與五款校正。
- 平均分數與投票統計分開。合併初始時 directCount、comparisonCount、evidenceCount 都為 0；另有明確的初始值存在標記，未知列沒有初始值。
- RD 採保守初始不確定度（現有模型上限 3），不以來源票數推算縮小後的 RD。這是初始化政策，不是對舊票信心的精確合成。
- 計分器辨識初始值存在時，不走「第一票直接覆蓋」分支；後續真實投票按既有更新公式計算，只新增真實票數。
- 有初始值但無新票的瀏覽文字標示「由舊屬性換算／新投票 0」，不可顯示「已獲 1 票」。範例可使用初始值；相近排序須保留保守權重，不能把兩個來源重複當成兩個維度。

### B. 重建與離線舊題

- 重建先載入合併初始值，再只重播切換之後屬於新屬性的有效答案；不得把初始值已吸收的舊歷史再計一次。
- 合併遊戲時，初始值來源 subject 的對應也需更新或保留映射。來源與目標都有初始值時，必須有明確、可重建的合併規則；不能依資料列先後決定。
- 分開「可抽題」與「可接受有效舊簽章回答」。切換後停止抽舊題，但仍驗證原始題目的屬性、兩款遊戲、方向及有效期限，再處理舊答案。
- 舊得分取勝答案映射到固定方向時用 10−分數，A_HIGHER／B_HIGHER 對調；舊條件取勝保持原方向。SIMILAR 保持不變。新的雙端答案沿用既有 highPole 換向。
- 同一 responseId 只能計一次；儲存來源題目識別與映射版本，使重送及背景重播不重複換向。
- 舊答案不先改動已凍結的初始值再投一次新票；只能透過一條明確的映射路徑納入後續更新。

### C. 原子切換與回復

- 啟用時重抓最新正式狀態，對照預覽及五款精確 ID；若來源缺失、版本不同或已有同名批次，先停止並產出差異。
- 以受控批次建立新屬性與兩端原文、來源快照及初始狀態，再切換抽題／公開目錄；在此之前保留現有服務。
- 同一批次的重跑要冪等。切換、背景重建及投票写入不能交錯到不同初始版本。
- 快照與增量一併發布，確保舊快取不繼續把新舊三個欄位都當成獨立可投票維度。
- 回復優先停用新抽題、恢復舊欄位曝光；不刪除任何新投票、映射收據或來源快照。回復後新票如何呈現另行處理，不把單一新值虛構為兩筆舊答案。

## 必須通過的驗收

- 已知初始值＋第一筆直接分數／比較答案：維持合理更新，新票數恰增 1。
- 未知初始值＋第一筆直接分數：保留既有首次評分行為。
- 五款校正與快餐結果可從初始來源重建，舊資料逐筆不變。
- 背景重建、重跑 migration、合併遊戲後結果可重現，沒有雙重計票。
- 切換前快取的兩種舊題，切換後重送成功且正反向正確；過期或篡改簽章仍拒收。
- 桌面／手機瀏覽、總表排序、兩端範例、直接評分歷史、相近遊戲與收藏抽題都辨識合併初始值。
- 回復後舊欄位可用，所有新舊投票與來源快照仍可查核。

以上 A、B 的程式與隔離資料庫測試完成之前，不產生會自動啟用的 migration。
