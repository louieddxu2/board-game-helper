## 原因與修正

收藏匯入 SQL 只去除空格並轉小寫，因此留下 `mountaingoats:legacy`；即時新增遊戲則去掉標點，寫入 `mountaingoatslegacy`。兩個來源產生了不相等的比對鍵。

`src/shared/nameNormalization.ts` 現在提供唯一的 `normalizeName()`：NFKC、去除前後空白、轉小寫，再移除空白、標點及符號。Worker、前端搜尋與 Excel 匯入器共用該函式；原名稱照原樣儲存、顯示。

規則版本標籤的「擴充／擴」語意比對仍保留，但不再用這種縮寫結果填入 `games.normalized_name`；它們也儲存相同的正式名稱比對鍵。已有版本只在該主遊戲的索引關係範圍內比對。

新增一次性資料修正，限定固定 ID、原顯示名稱與不一致鍵值，沒有新增資料庫 trigger 或使用者讀取時的修補掃描。原有發布／migration 檢查會在本機驗證所有遊戲及別名的鍵值，讓後續 SQL 匯入無法再沿用不同的標準而通過檢查。

原 API 合併交易抽成 `worker/data/gameMerge.ts`，API 與授權維護操作共用，沒有另寫一套合併 SQL。編輯者權限、請求與回應格式保持一致。這次透過官方遠端 D1 binding 執行同一段交易，沒有建立網站帳號或登入 session。

正式資料修正已生效；共用函式與合併程式的整理只提交本機 Git，未發布新版 Worker。現行 Worker 本來就使用相同的名稱正規化演算法，修正儲存鍵後即可正確比對。
